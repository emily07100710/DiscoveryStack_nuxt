# 正式文章審稿工作台

這是擁有人逐篇備稿、目前綁定的客戶在 LINE 審稿、再發布到 Do Alignment 部落格的手動流程。它不是自動產稿或模型訓練，也不啟用全站排程、每週內容服務或其他客戶的發布目標。

## 審稿流程

擁有人先在「每週內容」的正式文章區選擇 Do Alignment，編寫完整文章並明確確認送出。系統先保存備稿授權，建立客戶網站的私有草稿，再發送一張只有「開啟審稿工作台」的 LINE 卡片。舊測試稿的同意、舊閱讀 token 或舊訊息按鈕不能授權正式發布。

客戶開啟工作台後，可閱讀、修改文字與版面區塊、加入配圖與替代文字、設定封面，或留下修改意見。修改意見不會自動交給 AI 改稿；擁有人處理後，需明確送出新版審稿通知。同一篇新版仍須由客戶再次核准。

「同意並發布」只核准畫面上的已儲存版本及其圖文雜湊。未儲存修改、缺少圖片授權／替代文字、身份或公司綁定變更會阻擋操作。核准後版本固定，不能再修改或撤回；發布後由 Do Alignment 原有部落格後台下架或封存。

核准後立即執行一次發布，不等待每週排程。只有簽章收據和另外一次當前公開狀態核對都通過，才顯示公開文章連結。服務逾時或暫時故障可能延後結果；擁有人只能重試完全相同的核准版本，不可趁重試改稿。已在網站下架／封存的文章不會被重試重新公開。

## 圖片與身份

圖片只接受 JPEG／PNG／WebP，最多 1 MiB 原檔，必須聲明有使用權；伺服器限制像素、去除 metadata 並轉成不超過 512 KiB／1920 px 的靜態 WebP。草稿圖片保存在客戶網站既有私有儲存空間，經已登入、目前綁定客戶的 POST 預覽，不把 LINE token 放入 URL 或瀏覽器持久儲存。

每次客戶操作重新核對 LINE ID token、目前公司綁定及工作台有效期限。發布、圖片與私有預覽均使用固定 doalignment.com 端點、專用 HMAC 密鑰、時間窗與 nonce。客戶瀏覽器不能選擇站點、老師或伺服器憑證。

## 部署與驗收

DS 的 0057 只新增五張工作台表；先備份正式 schema／ledger、核對 0056 baseline、完整 SQL 與資料筆數，再新增表及 migration ledger。客戶網站的接收端另依其既有備份／還原演練、Repository Gate、RLS、候選版本無流量驗證、migration、切流及 smoke 流程部署。

DS `.env.example` 的五項 `NUXT_ARTICLE_WORKBENCH_*` 與客戶網站六項 `DS_ARTICLE_WORKBENCH_*` 只存正式主機的私密設定。功能預設關閉；完整配對、目前客戶綁定、既有 LIFF／LINE 發送設定及已核對擁有人都缺一不可。不得將範例值、私密設定檔或教師 ID artifact 提交到 Git。

本機測試、建置與部署成功不等同實機驗收。仍需客戶在新版 LINE 工作台登入、編輯／配圖、重新核准，並核對實際公開文章與圖片；管理者不代替客戶按核准。
